# Sydney Traffic Volume Dataset - Feature Reference

Benchmark data for Sydney hourly traffic volume modeling with crash-context features.

- **Source**: NSW Traffic Volume Counts API
- **Region**: Sydney metropolitan area
- **Years**: 2022, 2023, 2024
- **Download script**: `fetch_traffic_data.py`
- **Crash alignment script**: `align_crash_data.py`
- **Exploration script**: `read_data.py`

## 3. `traffic_hourly_sydney_{year}_aligned.csv` - Final Traffic + Crash Features

These are the final modeling-ready files generated by `align_crash_data.py`.

| Year | Rows | Columns | Active Stations |
|------|------|---------|-----------------|
| 2022 | 524,515 | 19 | 112 |
| 2023 | 505,102 | 19 | 84 |
| 2024 | 441,146 | 19 | 72 |

**Format**: one row per `(station_key, date, hour)`.

Before crash features are joined, `align_crash_data.py` collapses duplicate multi-stream traffic rows at the same `(station_key, date, hour)`:

- `volume` is summed across all reported streams.
- `daily_total` is summed across all reported streams.
- Shared metadata and calendar fields are retained.

For example, if station `55307` has two rows on `2022-01-12` at hour `0`, their `volume` values are added into one final hourly volume.

### Crash Context Features

The aligned files contain all 14 traffic columns plus these 5 crash-derived columns:

| Column | Type | Description |
|--------|------|-------------|
| `crash_count` | int | Number of matching crashes within 5 km for the same `(station_key, month, day_of_week, hour)` |
| `crash_severity_sum` | int | Sum of severity scores: Fatal = 5, Injury = 2, Towaway = 1 |
| `crash_injury_sum` | int | Total persons injured or killed across matching crashes |
| `crash_fatal_count` | int | Number of fatal crashes among matching crashes |
| `crash_wet_count` | int | Number of matching crashes on wet road surface |

## Crash-Traffic Alignment Method

The crash dataset does not provide an exact calendar date. It provides month, day of week, and a two-hour time window. For privacy reasons, exact crash dates are not available, so alignment is a statistical density join rather than an exact event join.

| Dataset | Temporal Resolution | Example |
|---------|---------------------|---------|
| Traffic | Exact date + hour | `2022-03-15, Tuesday, 08:00` |
| Crash | Month + day of week + two-hour window | `March, Tuesday, 08:00-09:59` |

This means we cannot answer:

- "Did a crash occur near station 55304 on March 15, 2022 at 8:00 AM?"

But we can answer:

- "On a typical Tuesday morning in March, how many crashes occur near station 55304 during the 08:00-09:59 window?"

### Step by Step

1. Load NSW crash data from `nsw_road_crash_data_2020-2024_crash.xlsx`.
2. Filter crashes to 2022, 2023, and 2024.
3. Map month and day-of-week names to integers.
4. Expand each two-hour crash window into two hourly slots.
5. Compute the Haversine distance between each crash and all 299 Sydney stations.
6. Keep crash-station pairs within 5 km.
7. Aggregate crash features by `(station_key, month, day_of_week, hour)`.
8. For each traffic year, merge multi-stream traffic rows by `(station_key, date, hour)`.
9. Left-join crash features to the merged traffic table on `(station_key, month, day_of_week, hour)`.
10. Fill missing crash features with zero and save the aligned CSV.

### Interpretation

A single crash record maps to many traffic rows. For example, a crash on some Tuesday in March between 08:00 and 09:59 near station `55304` matches every Tuesday in March at hours 8 and 9 for that station. Therefore `crash_count` is a recurring time-slot crash density feature, not a real-time event flag.

This is useful for prediction, anomaly detection, and contextual modeling because it captures typical crash risk by location, month, weekday, and hour.

## Table Relationships

```
stations_sydney.csv (station_key)
  |
  +-- 1:N -- traffic_hourly_sydney_{year}.csv
  |
  +-- 1:N -- traffic_hourly_sydney_{year}_aligned.csv
  |            |
  |            +-- crash features joined on station_key, month, day_of_week, hour
  |
  +-- 1:N -- yearly_summary_sydney_{year}.csv
```

`station_key` is always an integer join key.

## Recommended Workflow

```bash
# Step 1: Download raw traffic data
python fetch_traffic_data.py

# Step 2: Merge multi-stream traffic rows and attach crash features
python align_crash_data.py

# Step 3: Explore the latest aligned data
python read_data.py --year 2024
python read_data.py station 55304 --year 2024
python read_data.py crash --year 2024
```
